# Backend parity and full CRS latency

The Go and pure Rust backends agreed on all 99 request and response ACKs across 35 policy configurations. The previous Rust artifact differed on 31 of the 97 ACKs that could be compared. It rejected the literal-regex policy at startup, preventing the other two comparisons. It allowed 11 requests that Go denied, denied 6 requests that Go allowed, returned a different denial status and rule ID on 3, and reported different audit fields on the other 11. The Go results were identical across builds. The comparison checks every returned field except the independently generated transaction ID, which the client uses to correlate responses. [Full parity results](993a588-parity.json) · [Previous differences](993a588-before.json)

The cases cover phase order, projected argument counts and exclusions, form and JSON argument names, multiple matched fields, chained actions, scoped matched variables, marker execution, regex flags and operands, and correlated responses. Two policies load the complete CRS, one with representative HAPTIC catalog settings. These results qualify the listed cases. [Replay instructions](../README.md#compare-policy-decisions)

Each workload used 12 alternating pairs of 300 transactions per backend after warmup, over a persistent Unix socket to the release SPOA hub v0.13.0. Both libraries loaded OWASP CRS 4.25.0 on an AMD Ryzen 7 5700X3D, with hub processes on CPUs 5 and 6 and the client on CPU 2. Other test jobs shared the host. Values are medians of batch statistics. The paired p50 change compares adjacent batches. [Raw timings, process memory and artifact hashes](993a588.json)

Both release libraries were built from plugin commit `993a58863147860d2803c3003940ec6eb5902440`. Go used Coraza v3.8.1 with multiphase evaluation enabled. Rust used zentinel-modsec `b206f2fb39d854628e755f95a0afdfb2d7ee1576` with the Rust detector.
