# Full CRS latency through the SPOA hub

Both release plugins used commit `786d0143ddaa1420d630962122e7b0082b44ed34` and the same Cargo.lock. The Go build used Coraza v3.8.1. The native build used zentinel-modsec `b5c2ced` with its Rust detector. Each hub loaded its selected library from a directory containing both files. The client sent one request at a time over SPOP 2.0 on a persistent Unix socket. Each workload ran 12 interleaved pairs of 300 requests after warmup, for 3,600 measurements per backend. The table gives medians of the batch percentiles, and the paired percentage compares neighboring batches. The correlated response workload times both socket exchanges; every pair showed lower p50 latency for the Rust plugin across all four workloads. [Raw measurements and all probe fields](786d014.json) · [Workloads and replay instructions](../README.md)

Both engines loaded Coraza's recommended configuration, the OWASP CRS 4.25.0 setup and all rule files, and two phase-control rules. Every tested SPOA variable agreed after omitting generated transaction IDs. The checks included benign allows, the CRS method-denial rule `949110`, form and JSON body denials, and a denial in phase 4 against a retained transaction. Phase scheduling and aggregate argument counts can still differ on other policies. [Engine selection](../../../README.md#choosing-an-engine-for-a-policy)

The host used an AMD Ryzen 7 5700X3D with Linux 7.3.3-1-cachyos and the performance governor. Both hub processes used CPUs 5 and 6, with one Tokio worker and up to two blocking threads. The client used CPU 2 on a separate physical core. The hub was the published v0.13.0 amd64 glibc2.36 binary. The plugins were built with rustc 1.96.1; the Go compiler was go1.27.4. [Hub release](https://github.com/haproxy-haptic/haproxy-spoa-hub/releases/tag/v0.13.0)

Only the Go library contained Go build metadata and the runtime symbols `runtime.main`, `crosscall2` and `_cgo_init`. The Rust artifact also passed the check for absent libinjection C entry points. The final request-profile hub PSS was 82.3 MiB for Go and 48.8 MiB for Rust. Peak RSS was 87.4 and 53.9 MiB. With response tracking, PSS was 83.3 and 47.2 MiB and peak RSS was 88.2 and 52.2 MiB respectively. These figures include the hub and reflect the allocator and garbage collector state in this run.
